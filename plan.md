# Watree — real garden accounts and device connectivity

The user has requested that the existing dashboard become usable for real gardens: fix inactive controls, add account creation and editable garden settings, and allow an actual watering setup to connect. Preserve the botanical design and current page structure.

Use the starter's real Manus OAuth sign-in/sign-up and validated application sessions. Enable the managed server and MySQL database. Keep anonymous demo browsing as an explicitly separate mode; signed-in users create empty real gardens rather than inherit sample plants. Persist owner-scoped gardens, plants, device registrations, sensor history, commands, and acknowledged watering events. A garden switcher selects among the owner's gardens. Account identity comes from authenticated user records, never hardcoded Jamie Davis.

Implement a hardware-agnostic outbound HTTPS protocol because the controller and existing firmware are not yet specified. An owner registers a device and receives a high-entropy token once; store only its hash. Firmware posts telemetry and heartbeat, polls bounded expiring watering commands, then acknowledges actual delivery. Tokens support rotation and revocation. Map each plant to a registered device and channel. Do not claim that registration alone connects or programs the hardware; status becomes online only after an authenticated device request. Provide downloadable protocol docs and a Raspberry Pi Python integration example with a dry-run safety default; tailor firmware when the user supplies the controller details.

Live manual watering queues a command, never fabricates completion or increases moisture. Actual delivered amounts enter watering history only on device acknowledgement. Fresh telemetry can enqueue automatic commands when enabled, below a per-plant threshold, and within bounded dose, reservoir, freshness, cooldown, and duplicate-command limits. Device firmware must independently enforce pump duration, calibration, idempotency, and stop conditions. No remote command is sent while testing. Claim commands atomically, expire old commands, reject cross-owner/device data, validate all measurements and channels, and support cancellation before claim.

## Structure

`drizzle/schema.ts` and committed additive migrations hold garden/account/device/telemetry/command data. `server/garden/` owns protected tRPC account and garden operations plus token-authenticated device HTTP routes; register them in existing `server/routers.ts` and `server/_core/index.ts`. `shared/watree-live.ts` defines the frontend payload contract. `client/src/lib/watree.tsx` adapts the existing UI to either demo state or protected live queries; `client/src/pages/AccountSettings.tsx` and `DevicesPage.tsx` provide real onboarding, garden/profile edits, and connection setup. Existing overview, plants, analytics, and automation use real cloud data when a real garden is selected, show missing/stale data accurately, and provide error and pending feedback. `client/public/integration/` contains protocol documentation and safe firmware examples. Container deployment uses the existing Dockerfile and `/api/health`; Preview uses the Express development server on port 3000.
